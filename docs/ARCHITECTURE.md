# معمارية PalmTrace (للمطورين ووكلاء البرمجة)

## الخادم (`backend/`)

```
server.js            يستقبل الطلب ← CORS ← ملفات الواجهة ← بوابة الدخول والصلاحيات ← routes/* بالترتيب
startup.js           مهام بدء التشغيل: بيانات البداية، الترحيلات القديمة، مفتاح Gemini
config.js            المسارات وقراءة .env
db.js                فتح قاعدة SQLite وتشغيل الترحيلات المرقمة (المرحلة المبكرة)
auth.js              الجلسات (Bearer token) + صلاحيات المدير على المسارات الحساسة
access.js            مستوى الوصول: full / staff / investor + تصفية بيانات bootstrap + قيود المسارات
lib/http.js          sendJson, parseBody, serveStatic
lib/helpers.js       دوال مشتركة (السجل، الإعدادات العامة، تحويل أكواد الزكاة …)
lib/agro.js          الطقس (Open-Meteo ET₀) والقمر الصناعي (AgroMonitoring NDVI) — كل الاتصالات الخارجية هنا
lib/bootstrap.js     بناء حمولة /api/bootstrap وتخزينها مؤقتاً ونسخة مُصفّاة لكل مستخدم
routes/*.js          كل ملف مجموعة مسارات، ويُرجع NEXT إذا لم يطابق الطلب
migrations/runner.js الترحيلات المرقمة (جدول schema_migrations)
migrations/versioned NNN_name.js  — ترحيل جديد = ملف برقم جديد، ولا يُعدّل ترحيل منشور
migrations/*.js      ترحيلات قديمة تعمل عند كل تشغيل (متوافقة مع التكرار)
seeds/               بيانات البداية (SEED_DEMO_DATA=true للمزرعة التجريبية)
tests/*.test.js      اختبارات الـ API (npm test) — تشغّل خادماً حقيقياً على قاعدة مؤقتة
```

**المزامنة الجزئية (bootstrap v2):** الأشجار والعمليات عليها `row_version` بيتحدث بـ triggers (الترحيلات 006 و007)، والحذف بيتسجل في `*_tombstones`. التطبيق بيبعت `palmsSince` و`opsSince` وبيستلم التغييرات بس، بعدين بيتحقق من العدد و`idHash`. لو اسم في جدول مرجعي اتغير (`SYNC.*.lookupsHash`)، القائمة بتتبعت كاملة. لو ضفت حقل جديد يظهر مع الشجرة من جدول تاني، ضيف الجدول ده لـ `lookupsHash`.

**إضافة مسار جديد:** ضعه في ملف `routes/` المناسب. لو كان المسار حساساً، أضف قاعدته في `auth.checkRoleAccess` أو `access.checkScopedRoute`.

**مستويات الوصول (`access.js`):**

| المستوى | الأدوار | ماذا يرى |
|---|---|---|
| full | admin, super_admin, tenant_user, customer_care | كل شيء |
| staff | engineer, worker, warehouse_mgr, nursery_mgr | بيانات المزرعة كاملة، أما العقود والزكاة فيرى ما يخصه هو فقط، ولا تظهر له بيانات تواصل المستثمرين |
| investor | من دوره مستثمر فقط | قطعه (من العقود أو صلاحيات العرض، ومعها القطع الفرعية)، وأشجارها، وعملياتها، وحصادها، وعقوده، وزكاته |

## الواجهة (`frontend/`)

سكربتات عادية (ليست modules) تُحمّل بالترتيب في `index.html`. **الترتيب مهم.**

```
js/auth.js          الجلسة: يضيف Authorization لكل طلب /api، الدخول دون اتصال (PBKDF2)
js/store.js         الحالة المحلية (localStorage)
js/api.js           الاتصال بالخادم والمزامنة: ListSync (أشجار/عمليات بالتغييرات + IndexedDB) ومزامنة الزكاة
js/voice-intent.js  فهم الأوامر الصوتية (دوال بحتة، بيستخدمها التطبيق والخادم والاختبارات)
js/voice-assistant.js  زر 🎙️ ولوحة التسجيل والتأكيد (خارج #app)
js/app/01..13-*.js  الشاشات والدوال حسب الوحدة
js/app/14-actions-NN.js   معالجات الأزرار (data-act) مقسمة على أجزاء
js/app/15-actions-dispatch.js  act(): يمرّ على الأجزاء بالترتيب
js/app/16-boot.js   المستمعات العامة وبدء التشغيل
sw.js               الكاش للعمل دون اتصال — حدّث رقم الإصدار وقائمة الملفات عند إضافة ملف
```

**إضافة ملف جديد للواجهة:** أضفه في `index.html` وفي قائمة `ASSETS` في `sw.js`، وارفع رقم `?v=` و `CACHE`.

**قاعدة للتقسيم:** الكود في المستوى الأعلى من الملف (خارج الدوال) يجب ألا يستدعي دالة معرّفة في ملف يُحمّل بعده.

## الذكاء الاصطناعي والبيانات الحقيقية

- **المساعد الصوتي:** `VoiceIntent.understand(text, ctx)` بيرجّع مسودة فيها معرفات حقيقية و`issues`. أنواع العمليات بتتطابق بالكلمات (IDF + قاموس مرادفات `SYN`)، فلو فيه كلمة عامية مش بتتفهم، ضيفها لـ `SYN`. الاختبارات في `backend/tests/voice-intent.test.js`.
- **NDVI:** `POST /api/agro/ndvi/sync` بينشئ مضلع لكل قطعة رئيسية ليها حدود، وبيسحب التاريخ ويخزنه. `GET /api/agro/ndvi` بيقرأ من قاعدة البيانات بس، والمستثمر بيشوف قطعه بس.
- **الطقس:** `GET /api/agro/weather`، والنتيجة بتتخزن مؤقتاً 3 ساعات.
- **المفاتيح:** أي مفتاح جديد يتضاف لـ `SECRET_SETTING_KEYS` في `lib/helpers.js` عشان مايوصلش للمتصفح.
