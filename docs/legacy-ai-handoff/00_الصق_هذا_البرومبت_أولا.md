# برومبت الافتتاح — الصقه كما هو في شات الوكيل

انسخ النص بين الخطوط والصقه كأول رسالة في Copilot Chat / Agent.

---

أنت مهندس مسؤول عن تطوير نظام إدارة النخيل والفسائل (PalmTrace).

هذا مستودع PWA عربي RTL، Offline-First، ملف واحد للمنطق تقريباً:

- `index.html` نقطة الدخول
- `js/store.js` الحالة المحلية (localStorage مفتاح `palmtrace_v5`)
- `js/app.js` الواجهة، التوجيه، الصلاحيات، كل الشاشات (~3500 سطر)
- `css/app.css` الهوية البصرية
- `sw.js` كاش الخدمة الحالي `palmtrace-v33`
- `manifest.json` تثبيت PWA

قواعد صارمة:
1. النظام للنخيل والتمور فقط. لا تضف زيتوناً أو محاصيل أخرى إلا إذا طلبت ذلك صراحة لاحقاً. المسمى دائماً: نخلة / نخيل / فسيلة / تمر.
2. لا تكسر التكويد المعتمد:
   - نخلة مزروعة: `{قطاع}-{قطعة+حرف}-{F|N}{تسلسل3}-{MMYY}`
   - مثال: `03-12A-F045-0325`
   - حرف المصدر قبل رقم النخلة وليس في أول الكود
   - فسيلة مقلوعة: كود الأم + `-OS{تسلسل}-{MMYY}` مثال `03-12A-F045-0325-OS01-0825`
   - عند زراعة الفسيلة تأخذ كود موقع جديد وتحتفظ بالكود المؤقت للنسب
3. الواجهة عربية RTL. لا تظهر نصوص حالة إنجليزية خام للمستخدم (pending → معلّق، approved → معتمد).
4. نمط الأحداث: delegation عبر `data-go` و `data-act` على `document`. لا تربط onclick داخل HTML إلا للضرورة. عند إضافة شاشة اتبع نفس النمط.
5. بعد أي تعديل على الملفات المخزّنة في الكاش زِد رقم `CACHE` في `sw.js` حتى لا تبقى نسخة قديمة.
6. الحسابات التجريبية وكلمة المرور `1234`: admin / engineer / worker / investor / nursery
7. لا تحذف خصائص تعمل: مسح QR، مزامنة محلية، عمليات جماعية، أسمدة، ربط المركب بنوع العملية، المشتل، الزكاة، بوابة المستثمر، الخريطة، الاستيراد.
8. عدّل بأقل فرق ممكن. اقرأ الدالة المعنية قبل التعديل. لا تعِد كتابة `app.js` من الصفر.
9. بعد كل مجموعة تعديلات: `node --check js/app.js` و `node --check js/store.js` إن أمكن.

المهمة الحالية: افتح المشروع، شغّله محلياً، ثم انتظر تعليمات التعديل مني. أولاً لخّص بنية الملفات والدوال الرئيسية في `app.js` (التوجيه، الصلاحيات، التكويد، العمليات الجماعية) في نقاط قصيرة.
