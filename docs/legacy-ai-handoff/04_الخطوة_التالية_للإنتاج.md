# ما بعد الـ MVP — مهام جاهزة لتوجيه الوكيل

اعمل بنداً واحداً في كل رسالة. لا تطلب «ابن النظام من الصفر».

ترتيب مقترح:

1. فصل `app.js` إلى وحدات بدون تغيير السلوك:
   `router.js`, `coding.js`, `ops.js`, `nursery.js`, `users.js`, `views/*.js`
   مع الإبقاء على نفس `data-act`.

2. طبقة API وهمية (`api.js`) تغلف `Store` حتى يمكن لاحقاً استبدالها بـ REST.

3. خلفية حقيقية (يُفضل لاحقاً خارج هذا المجلد):
   Node + Express أو .NET Minimal API
   SQLite ثم PostgreSQL
   جداول: users, sectors, plots, palms, offshoots, operations, yields, zakat

4. مزامنة حقيقية:
   طابور IndexedDB → POST عند عودة الشبكة
   تعارض: آخر كتابة معتمدة من المشرف تفوز، والميدان يبقى معلقاً

5. تطبيق موبايل اختياري بعد استقرار الـ PWA (لا تبدأ بـ MAUI قبل استقرار المنطق).

عند طلب بند، اكتب للوكيل مثلاً:

«نفّذ البند 1 فقط: استخرج دوال التكويد `buildCode` و `nurseryCode` و `mmYY` إلى `js/coding.js` وصِلها من `index.html` دون تغيير أي شاشة.»
